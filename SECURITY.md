# Безопасность MedAI

## Реализовано в коде

- Сессия браузера — `HttpOnly + SameSite=Strict` cookie; `Secure` в production.
  Токен веб-сессии не сохраняется в `localStorage`/`sessionStorage`.
- Двойная CSRF-защита cookie: `X-CSRF-Token`, проверка Origin/Referer и Fetch Metadata.
  Bearer остаётся для служебных клиентов с явным заголовком `X-Client-Type: api`.
- PBKDF2-SHA256, 600 000 итераций, случайная соль. Новые пароли — не менее 12 символов.
  Старые короткие пароли не ломаются: назначьте пользователям смену пароля при следующем входе.
- Лимиты регистрации, логина, чата и ИИ-сводок. Для нескольких реплик необходим Redis.
- Проверка роли, владельца и филиала. Врач не может самостоятельно сменить филиал.
  Пациент меняет филиал только с текущим паролем; плановые записи переносятся транзакционно.
- CSP, HSTS (в HTTPS), `frame-ancestors 'none'`, `nosniff`, `Permissions-Policy`,
  запрет кэша приватных API и документов. OpenAPI/Docs отключены в production.
- Документы: лимит 8 МБ, проверка magic bytes и MIME, ASCII-имена без CR/LF,
  принудительное скачивание, sandbox CSP, `no-store`. Вирусный сканер не встроен.
- Локальный серверный OCR: очередь, отдельный worker, лимиты страниц/времени/объёма,
  доступ по владельцу, без передачи документа внешним API. См. `OCR_SETUP.md`.
- Внешний LLM: пользовательский текст очищается от email/телефонов/URL/номеров документов;
  имена и ID не передаются. Врачебные инструменты получают HMAC-псевдонимы вместо ID БД.
  DLP-фильтр не гарантирует полную анонимность: без согласованного обработчика отключайте `LLM_API_KEY`.
- ИИ-чат и текст анализов: модель читает распознанный документ только по явному запросу
  (`read_my_document` / `get_patient_document`), только у владельца или врача своего филиала.
  Перед отправкой вырезаются поля бланка — ФИО, дата рождения, адрес, врач, учреждение;
  лабораторные показатели, единицы и нормы остаются, иначе ответ модели бесполезен.
  Лимит `CHAT_DOCUMENT_TEXT_MAX`, каждый доступ пишется в аудит (`chat.document_text`,
  без содержимого). Полный запрет — `CHAT_DOCUMENT_TEXT=false`. См. `README.md`.
- Аудит регистрации, входа, переноса филиала, просмотра медкарты/замеров и удаления документов.
  Журнал не содержит самих медицинских текстов, но не является юридически неизменяемым WORM-хранилищем.
- Backend не публикуется из Docker; доверяет только Nginx `172.30.0.10`.
  Nginx ограничивает запросы, размер тела, TLS и security-заголовки.
- Зависимости Python закреплены с хэшами (`requirements-lock.txt`), Node — `package-lock.json`.
  CI включает `pip-audit`, `npm audit`, тесты, lint, build и smoke-test чистой миграции.

## Перед production

1. **Резервная копия.** Не обновляйте реальную БД без консистентной копии `.db`, `-wal` и `-shm`.
   Проверьте восстановление на копии. Не копируйте открытую SQLite базу обычным `copy` во время записи.
2. **Миграция.** Существующие совместимые базы автоматически получают Alembic `0001`–`0003`.
   Несовместимая база останавливает запуск вместо удаления таблиц. Для такой базы требуется ручной
   перенос. Старые таблицы `legacy_*_0001` сохраняются, файлы `stored_path` автоматически не переносятся.
3. **TLS.** Положите сертификат доверенного CA и закрытый ключ:
   `certs/fullchain.pem`, `certs/privkey.pem`. Права ключа — только администратору/Nginx.
   Не используйте self-signed для реальных пациентов. Настройте автоматическое продление.
4. **Сеть.** Откройте наружу только 80/443. Не публикуйте backend:8000 и SQLite volume.
   Firewall хоста, обновления ОС, отдельная учётная запись без административных прав обязательны.
5. **Конфигурация.** В `.env` (не в Git):
   ```
   APP_ENV=production
   ENFORCE_HTTPS=true
   SECURE_COOKIES=true
   CORS_ORIGINS=https://medai.example.ru
   DATABASE_PATH=/data/medai.db
   SESSION_TTL_DAYS=7
   LLM_API_KEY=
   LLM_BASE_URL=https://plusvibeapi.ru/v1
   ```
   Запуск: `docker compose up --build -d`. Отсутствие сертификатов должно останавливать запуск.
6. **Защита данных.** Включите шифрование диска (BitLocker/LUKS), шифруйте бэкапы и ограничьте
   доступ администраторов. SQLite здесь не шифруется на уровне приложения. Настройте retention,
   удаление аккаунтов, экспорт/архивирование аудита и защищённое WORM/отправку логов.
7. **ПДн и LLM.** До подписания документов с обработчиком, privacy notice и согласий не включайте
   внешний LLM. Лучший вариант для медицинских текстов — локальная модель в защищённом контуре.
8. **Эксплуатация.** MFA для врачей/администраторов, менеджер секретов, антивирусная проверка
   документов, централизованный rate-limit/WAF, алерты на подозрительный доступ и регулярный
   внешний пентест всё ещё нужны. Локальные лимиты сбрасываются при рестарте процесса.

## Границы проверки

Проверены локальные исходники, тесты, свежая Alembic-схема, Python/Node audit и frontend build.
На машине аудита нет Docker: реальные образы, nginx с TLS и сетевая конфигурация требуют smoke-test
на сервере. Код не заменяет независимый пентест, юридическую проверку обработки ПДн и защиту хоста.
