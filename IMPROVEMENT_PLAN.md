# Единый план функциональных улучшений

Статус: план (не реализовано). Собран 2026-11-28 из gap-анализа кода и
стресс-теста анализов. Перекрытия с ROADMAP.md помечены. Уже воплощено в этой
серии (см. DOC_CATEGORIES_PLAN.md): категоризация документов, авто-названия,
ручная правка названия/категории, нормализация единиц.

## Принципы (не пересматриваем)

1. **Детерминизм в медицине**: оценку риска считает `rules.py`. Локальные
   нано-модели только ассистируют (подсказывают, извлекают, ищут) — не решают.
   Замена rules-движка ИИ — «не делаем».
2. **Медданные не покидают сервер**: никаких внешних сервисов с содержимым.
3. **Ручное всегда правит авто**: `title_source='user'` не перезаписывается —
   паттерн распространять на всё новое.
4. **Цифры OCR не переписываются** (инвариант `ocr_postprocess`); исключение для
   семейства «1049/л → 10^9/л» — только явным решением владельца.

## Батч А — быстрые победы UX (small, 1–2 дня)

- **A1. Мультизагрузка и Ctrl+V.** `DocumentsTab.tsx` + `documents.py`:
  `file` массивом, вставка изображения из буфера (событие paste) как новый
  документ. Тест: 3 файла за раз → 3 записи, порядок и статусы корректны.
- **A2. Полный список заметок врача — пациенту.** Сейчас виден только последний
  комментарий на дашборде. Эндпоинт `GET /api/notes/mine` (заметки по разборам
  пациента, врач-фильтр не нужен), блок «Заметки врача» в медкарте рядом с
  разборами. Тест: заметка врача видна пациенту, чужая — нет.
- **A3. Контактный телефон в профиле.** Колонка `users.phone`, поле в
  `Profile.tsx`/`Register.tsx`, `ProfileIn`. Филиал видит телефон пациента.
- **A4. Удалить `DEVELOPMENT_PLAN.md`** — план датирован 2025-01, перекрыт
  ROADMAP.md.

## Батч Б — уведомления пациенту (medium, 3–4 дня; из ROADMAP «Сейчас»)

- **Б1. `GET /api/notifications`** — без новой таблицы, derived-запрос:
  новые заметки врача с прошлого просмотра, завершённые приёмы с заключением,
  планируемый приём завтра; для врача — непрочитанные сигналы (как сейчас).
  Прочитанность: колонка `users.notifications_seen_at`.
- **Б2. Колокольчик в `Layout.tsx`** — бейдж с числом, выпадающий список
  последних 10, клик ведёт к цели (медкарта/разбор/приём). Мёртвая красная
  точка удаляется.
- **Б3. Тесты**: подсчёт непрочитанных, сброс при просмотре, изоляция ролей.

## Батч В — врач видит документы пациента (medium, 3–4 дня; из ROADMAP «Сейчас»)

- **В1. Эндпоинты**: `GET /api/doctor/patients/{id}/documents` и `.../download`
  с гвардом филиала (как у медкарты, `medcard.py`).
- **В2. Вкладка «Документы»** в `DoctorPatient.tsx` (список + просмотр текста).
- **В3. Честные формулировки**: hint в `DocumentsTab.tsx` — «видны вашему
  врачу филиала»; uploads остаются приватными между пациентом и своим филиалом.
- **В4. Аудит и прозрачность**: `document.viewed_by_doctor` в журнал; пациенту
  в списке документа — «врач открывал: дата» (последний факт).

## Батч Г — пароли, почта, бэкапы (small-medium, 2–3 дня)

- **Г1. `PUT /api/auth/me/password`** — старый + новый пароль, брутфорс-гвард.
- **Г2. `PUT /api/auth/me/email`** — только с текущим паролем; уникальность 409.
- **Г3. Секция «Безопасность»** в `Profile.tsx`.
- **Г4. Ночные бэкапы** (из ROADMAP «Сейчас»): `tools/backup_db.py`
  (`sqlite3 .backup` + ротация N копий) + строка в README о cron/Task Scheduler.
- Восстановление пароля по почте — **отдельно**, нужен почтовый канал; не здесь.

## Батч Д — структурированные анализы (large, 5–8 дней; ключ к динамике)

- **Д1. `services/lab_parse.py`** — детерминированный парсер «показатель →
  значение → норма → единицы» из `ocr_text_clean`: словарь синонимов
  (Гемоглобин/Hb, СОЭ/ESR…), регэксп строки таблицы, статус по норме.
  Философия правил: распознаём только подтверждённые пары, остальное —
  «не распознано».
- **Д2. Хранение**: колонка `documents.lab_values` (JSON) + парсинг в
  `process_one` + `backfill_lab_values()` для готовых документов.
- **Д3. UI**: в карточке документа — таблица показателей, отклонения
  подсвечены (тихая точка+текст, не пилюли), потерянные OCR-строки — «не
  распознано».
- **Д4. Динамика показателя**: `GET /api/documents/lab-trend?key=hemoglobin`
  — значения по датам из всех документов; график (recharts) в медкарте рядом
  с графиками замеров.
- **Д5. Чат**: инструменты `get_my_lab_values` и сравнение двух документов
  («сравни анализы от 12.10 и 27.11»).

## Батч Е — врач-флоу и роли (large, частями; частично ROADMAP «Дальше»)

- **Е1. Слоты и подтверждение приёмов** — якорь ROADMAP, отдельный план
  (справочник врачей, слоты, статус «подтверждена»).
- **Е2. Дневник самочувствия** — таблица `symptom_notes` (дата, текст, самочувствие
  1–5), CRUD пациенту, виден врачу в карточке. Не путать с жалобами приёма.
- **Е3. Направления**: врач создаёт «сдать анализ X» — пациенту чеклист в
  медкарте; связь с Д (категория нужного бланка).
- **Е4. Возрастные нормы** (F032 из TECH_DEBT_AUDIT): таблица порогов по
  возрастным группам, `rules.py` выбирает по возрасту.
- **Е5. Роль «администратор филиала»**: очная регистрация пациента, выдача
  кодов, просмотр audit-лога (read-only UI).
- **Е6. CSV-выгрузка пула пациентов** филиала.

## Не делаем

- Замена `rules.py` нано-моделью (детерминизм и объяснимость оценки риска).
- Автоправка цифр OCR без явного решения владельца.
- Восстановление пароля по SMS/почте без почтового канала.
- Выкладка медданных в любые внешние сервисы.

## Порядок и оценка

А (1–2 дн) → Б (3–4) → В (3–4) → Г (2–3) → Д (5–8) → Е (частями).
Каждый батч закрывается гейтами pytest + ruff + build, смоуком вживую и
коммитом по «го» владельца. Пересечения с ROADMAP.md: Б, В, Г4 — из «Сейчас»;
Е1 — якорь «Дальше»; остальное — новые пункты, ROADMAP перегенерировать после
Батчей А–Г.
