# Спектр-Диагностика · MedAI — медицинский сервис с ИИ

Версия для клиники «Спектр-Диагностика» (федеральная сеть медицинских центров, spdmed.ru).

Личный кабинет пациента + кабинет врача: пациент ведёт замеры здоровья и медкарту,
врач видит картину пациента целиком до и во время очного приёма.

Пользователь вводит показатели здоровья (давление, пульс, температура, SpO₂, вес, сон, шаги, вода),
а гибридный ИИ анализирует их и даёт рекомендации:

1. **База правил** — детерминированная экспертная система по медицинским нормам (ВОЗ/ESC/ESH):
   статусы `ok / warn / alarm` по каждому показателю, перекрёстные правила-комбинации,
   итоговый риск `green / yellow / red`.
2. **Языковая модель** (опционально) — персональный текст рекомендаций через OpenAI-совместимый API.
   Ключа нет / ошибка / таймаут → приложение честно пишет «ИИ-текст недоступен» и показывает нормы.
   **LLM не может изменить оценку риска** — её определяют только правила.

Сервис не ставит диагнозы и не заменяет врача; дисклеймер показывается на каждом анализе,
тревожные значения всегда ведут к совету обратиться к врачу (при критических — 103).

## Версия для клиники

- **Медкарта пациента** — анкета-анамнез (группа крови, аллергии, хронические заболевания,
  лекарства, операции, привычки) заполняется пациентом и дополняется врачом; видна врачу
  до и во время приёма.
- **Опросник Минздрава (приказ № 404н)** — 28 вопросов официальной анкеты ХНИЗ
  (диагнозы, симптомы-скрининги, факторы риска, шкала AUDIT-C) в пошаговой форме
  с прогресс-баром; тревожные ответы подсвечивают системы организма и карточку врача.
- **Приёмы** — пациент записывается и описывает жалобы заранее; врач видит жалобы,
  пишет заключение и рекомендации; пациент видит их в медкарте.
- **Риск-профиль по системам организма** — свежие замеры и анамнез сворачиваются в картину
  по системам (сердце и сосуды, дыхание, пищеварение, …) с чипсами «что повлияло».
- **Запись к реальному врачу** — из риск-профиля: онлайн-запись на поддомене города spdmed.ru,
  звонок филиалу или жалоба в приложении.
- **Кабинет врача** — общий пул пациентов филиала: сигналы (красный замер, тревожный опросник,
  плановый приём) поднимают пациента в «Требуют внимания»; ИИ-сводка пациента к приёму
  (DeepSeek по данным медкарты и замеров — не меняет оценку риска); комментарии к анализам.
- **Роли** — пользователи делятся на `patient` (по умолчанию) и `doctor`. Врачом можно стать
  только по одноразовому **коду приглашения** при регистрации.
- **Генерация кодов** (админ клиники, из корня репозитория):

  ```bash
  python tools/make_invite.py              # 1 код, срок 14 дней
  python tools/make_invite.py 5            # 5 кодов
  python tools/make_invite.py 5 --days 30  # свой срок действия в днях
  ```

  Просроченный код отклоняется при регистрации; коды, созданные до появления срока
  (expires_at IS NULL), остаются бессрочными. Филиал обязателен при регистрации
  любой роли (без него сервер отвечает 422). Отключение врача и отзыв его сессий:

  ```bash
  python tools/disable_user.py врач@клиника.ru            # отключить + отозвать сессии
  python tools/disable_user.py врач@клиника.ru --enable   # вернуть доступ
  ```

- **Бренд и контакты** меняются в одном месте — `frontend/src/brand.ts` (название, подзаголовок,
  телефон, сайт, логотип, карта городов → поддомены spdmed.ru). Палитра и шрифт сняты
  с реального сайта клиники (teal #00b8a9, Inter).
- **Приватность**: данные пациентов хранятся в SQLite локально; LLM-обогащение и сводка
  включаются только явным вписыванием ключа в `.env`.

## Стек

- **Backend**: Python 3.13 + FastAPI + SQLite (WAL), pbkdf2-хэши паролей, bearer-сессии
- **Frontend**: React 18 + TypeScript + Vite + Tailwind 4, графики recharts
- **Карта филиалов**: векторная, отрисована в палитре сайта — MapLibre GL + PMTiles-экстракты городов (`frontend/public/maps/*.pmtiles`, уже в репо). Перегенерация: скачать [pmtiles CLI](https://github.com/protomaps/go-pmtiles/releases) в `tools/bin/`, затем вырезать ббоксы из дневного билда `build.protomaps.com` (`--bbox=… --maxzoom=14`). Данные © OpenStreetMap contributors
- **Дизайн**: направление «Клинический свет» — светлая тема с 1px-хайрлайнами вместо теней,
  фирменный тил #00b8a9, шрифт Inter (синхронизировано с фирстилем spdmed.ru)

## Запуск

### Backend

```bash
cd backend
pip install -r requirements.txt
copy .env.example .env        # опционально: вписать LLM_API_KEY
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Если есть сборка фронтенда (`frontend/dist`), бэкенд сам раздаёт её — приложение целиком
открывается на http://127.0.0.1:8000 (SPA-fallback для роутов).

### Frontend (режим разработки)

```bash
cd frontend
npm install
npm run dev    # http://localhost:5173, /api проксируется на :8000
```

### Прод-сборка одним сервером

```bash
cd frontend && npm run build   # создаст dist/
cd ../backend && python -m uvicorn app.main:app --port 8000
```

### Подключение ИИ-текста

В `backend/.env`:

```env
LLM_API_KEY=sk-pv-...              # ключ PlusVibe (plusvibeapi.ru, оплата в рублях)
LLM_BASE_URL=https://plusvibeapi.ru/v1
LLM_MODEL=deepseek-v4.1-flash-1017
CHAT_MODEL=deepseek-v4.1-flash-1017
```

После перезапуска бэкенда в анализе появится блок «Рекомендации ИИ» с персональным текстом.

PlusVibe — внешний обработчик данных: во всех трёх каналах (анализ замеров, ИИ-сводка
врача, чат-ассистент) ПДн обезличиваются перед отправкой — имя, пол и возраст пациента
заменяются на «Пациент N, X лет» (в чате врача — во всех списках пациентов), имена врачей
в заметках модели не передаются. Уходят только клинические данные: показатели, анамнез,
жалобы.

### Ассистент и распознанные анализы

Чат умеет читать текст документов, распознанных локальным OCR: пациент спрашивает
«объясни мои последние анализы», ассистент находит документ и разбирает показатели.
Врач делает то же для пациента своего филиала.

Доступ устроен так, чтобы медицинские ПДн не уходили наружу целиком:

- текст документа отдаётся **только по явному запросу модели** (`read_my_document`,
  `get_patient_document`), а не подмешивается в каждый запрос;
- проверяется владелец или филиал врача — как в остальных инструментах;
- перед отправкой вырезаются поля бланка: ФИО, дата рождения, адрес, врач, учреждение,
  номер заказа. Лабораторные показатели, единицы и референсные интервалы остаются —
  без них ответ модели бесполезен;
- размер ограничен `CHAT_DOCUMENT_TEXT_MAX` (по умолчанию 6000 символов), модель видит
  пометку `truncated`, если текст длиннее;
- каждый доступ пишется в аудит (`chat.document_text`, с размерами, без содержимого);
- `CHAT_DOCUMENT_TEXT=false` полностью отключает чтение текста, оставляя метаданные.

В интерфейсе есть кнопка «Исходный текст» рядом с распознанным документом: можно
сверить, что именно ушло модели, с бланком.

## Медицинские пороги правил (кратко)

| Показатель | Норма | Внимание (warn) | Тревога (alarm) |
|---|---|---|---|
| Давление | до 120/80 | 130–139/85–89, АГ 1 ст. (140–159/90–99), <90/60 | ≥160/100, ≥180/110, <85/50 |
| Пульс | 60–100 | 50–59, 101–120 | <50, >120 |
| Температура | 36.1–37.0 | 37.1–38.0, 36.0–36.1 | >39.0, >38.0, <35.0 |
| SpO₂ | 95–100 | 92–94 | <92 → срочно 103 |
| ИМТ | 18.5–24.9 | <18.5, 25–35 | <16, >35 |
| Сон | 7–9 ч | <7, >9 | — |
| Шаги | ≥3000, цель 8000–10000 | <3000 | — |
| Вода | ~30 мл/кг (≈2000 мл) | <1200, >4000 | — |

Комбинации: жар + учащённый пульс → инфекция; давление + пульс → стресс/кофеин;
недосып + высокое давление; лишний вес + низкая активность; гипотония + обезвоживание.

## Бэкапы (Г4)

Копия БД делается штатным Online Backup SQLite — согласованно даже при
работающем сервере (WAL):

```bash
python tools/backup_db.py                  # копия в tools/backup/, ротация до 14 копий
python tools/backup_db.py --keep 30        # хранить 30 копий
python tools/backup_db.py --verify         # открыть последнюю копию и посчитать строки
```

Ночное расписание:

- **cron** (Linux): `30 3 * * * cd /srv/medai && python tools/backup_db.py`
- **Task Scheduler** (Windows):
  `schtasks /Create /TN "MedAI backup" /SC DAILY /ST 03:30 /TR "python C:\srv\medai\tools\backup_db.py"`

Копии содержат медицинские данные — храните каталог рядом с БД или на
зашифрованном диске, наружу не выгружайте.
