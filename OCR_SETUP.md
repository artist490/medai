# Серверный OCR в MedAI

Распознавание выполняется **на сервере клиники**, через локальный LiteParse и модели
`OCRia-nano-1` на CPU. Загруженный документ и распознанный текст не отправляются в Hugging Face,
внешний OCR API или LLM. Веса модели лежат в репозитории (`backend/models/ocria-nano`),
поэтому скачивание из сети не требуется вообще.

## Уже реализовано

- API запуска: `POST /api/documents/{id}/ocr` → `202 Accepted`.
- Статус и Markdown: `GET /api/documents/{id}/ocr`; доступ только владельцу.
- Очередь SQLite, атомарный `claim`, восстановление прерванных задач.
- Отдельный worker-процесс: FastAPI не выполняет OCR внутри HTTP-запроса.
- Временные файлы с ограничением прав на Unix; автоматическая очистка.
- Ограничения: 8 МБ на документ, до 10 страниц, 180 секунд, 200 000 символов,
  20 задач в очереди, 3 попытки на документ.
- Вывод LiteParse ограничен по размеру; stderr и медицинский текст не пишутся в журнал.
- В интерфейсе: запуск, опрос статуса, ошибка/повтор, предпросмотр текста.
- OCR не изменяет медкарту, замеры и риск автоматически. Результат нужно проверить вручную.

## Где лежат веса

Веса `ocria-nano` **входят в репозиторий**: `backend/models/ocria-nano/` (≈45 МБ, 15 файлов).
После клонирования проекта OCR работает без скачивания: `backend/app/config.py` находит
`backend/models` автоматически, а worker передаёт путь LiteParse через `LITEPARSE_MODEL_DIR`.

Отдельная загрузка нужна только если вы намеренно ставите модель в системный каталог
(`%LOCALAPPDATA%\liteparse\models` на Windows, `~/.cache/liteparse/models` на Linux) —
этот путь тоже проверяется и имеет приоритет над репозиторием.

## Лицензия модели — прочитайте до использования

`backend/models/ocria-nano/LICENSE` — **OCRia-nano-1 Model License** (LlamaIndex, Inc.),
модифицированная OpenRAIL-M. Это **не open source** и она отдельная от Apache-2.0 LiteParse
и от MIT-лицензии самого MedAI. Существенные условия:

- **Ограничения по выручке/финансированию**: запрещено использовать, если организация
  за прошлый год получила более $2 млн выручки или привлекла более $2 млн инвестиций —
  кроме личного использования и исследовательских целей.
- **Запрет Competing Service**: нельзя использовать модель как часть сервиса
  распознавания документов, конкурирующего с LlamaParse/LlamaCloud.
- **Share-alike**: изменения весов и файлов модели распространяются только под этой же лицензией.
- **Attribution**: при распространении нужны ссылка на исходную модель и копия лицензии
  (файл `LICENSE` уже лежит рядом с весами и не должен удаляться).

Веса в репозитории — это их распространение (Distribution), поэтому условия выше
касаются каждого, кто клонирует проект. Для коммерческого использования сверх лимитов
нужен отдельный договор с LlamaIndex: https://www.llamaindex.ai/contact

## Локальный запуск (Windows/Linux)

1. Установите зависимости backend из `requirements.txt` или lock-файла.
2. Запустите backend и frontend обычным способом. В development worker стартует вместе с backend.
   Веса уже на месте, OCR включается автоматически. Явно запретить можно:
   ```env
   OCR_ENABLED=false
   ```
   Явное `OCR_ENABLED=true` требует установленной модели: просто включить флаг без весов нельзя.
3. В медкарте откройте «Документы», загрузите PDF/PNG/JPG/WebP и нажмите значок распознавания.

Проверить распознавание из консоли, не поднимая сервер:
```sh
lit parse scan.png --format markdown --ocr-backend ocria-nano --max-pages 1
```
Команде нужен `LITEPARSE_MODEL_DIR=<путь к backend/models>`, если веса не установлены
в системный каталог.

Для автономного сервера можно один раз установить веса из репозитория в системный каталог:
```sh
lit models pull ocria-nano --from backend/models/ocria-nano
```

## Production Docker

1. Убедитесь, что `requirements-lock.txt` содержит LiteParse (версия и хэши закреплены).
2. Скачивать веса не нужно: `docker-compose.yml` монтирует каталог репозитория
   `./backend/models` в контейнеры как `/models` (только чтение), а `LITEPARSE_MODEL_DIR=/models`
   уже задан. Наличие `backend/models/ocria-nano/det.onnx` — единственное условие.
3. Параметры OCR в production `.env` (включён по умолчанию, т.к. веса в репозитории):
   ```env
   OCR_ENABLED=true
   OCR_MAX_PAGES=10
   OCR_TIMEOUT=180
   ```
   Выключить: `OCR_ENABLED=false`.
4. Запустите обычный защищённый стек:
   ```sh
   docker compose up --build -d
   ```
   `ocr-worker` работает внутри Docker-сети, не имеет публичных портов и использует общий
   `/models` и `/data`. Frontend общается только с FastAPI, не с worker напрямую.

## Остаточные ограничения

- Worker не является полной песочницей: он ограничивает формат, время, объём, число задач и
  capabilities контейнера, но не защищает от всех возможных уязвимостей PDF/ONNX-runtime.
  Для недоверенных файлов рекомендован отдельный изолированный хост/VM и антивирус.
- Русские печатные документы поддерживаются через world-script recognizer. Реальный smoke-test
  успешно распознал «Анализ крови» и «Гемоглобин: 145», но `г/л` было ошибочно прочитано как `r/n`.
- Не используйте OCR как автоматический источник медицинских назначений, диагнозов или замеров.
- На машине разработки Docker не установлен, поэтому команды Docker описаны по конфигурации,
  а реальные образы требуют smoke-test на сервере.
