# Категоризация анализов и авто-заголовки документов — план внедрения

Статус: план (не реализовано). Автор: сессия ZCode, 2026-11-27.
Связанные документы: OCR_SETUP.md (серверный OCR), ROADMAP.md.

## Задача

Загруженные документы (фото/PDF анализов) должны:

1. **Категоризироваться по теме** — «кровь к крови»: анализ крови попадает в группу
   «Кровь», анализ мочи — в «Моча» и т.д.; в медкарте документы группируются по
   категориям.
2. **Автоматически получать название по теме** — вместо `774AE5E7_3864.jpg`
   документ называется, например, «Общеклинический анализ крови (СОЭ)».

## Утверждённые решения (согласовано с владельцем)

| Вопрос | Решение |
|---|---|
| OCR после загрузки | Запускается **автоматически** — тема и название определяются без лишних кликов |
| Ручные названия | **Не перезаписываются**: если пользователь ввёл название — оно остаётся |
| Гранулярность | **8 категорий** (см. справочник ниже) |
| Механизм классификации | **Детерминированные ключевые слова** по тексту OCR — без LLM: мгновенно, бесплатно и медицинский текст не покидает сервер (в духе правил `rules.py`) |

## Справочник категорий

Порядок фиксированный — он задаёт порядок групп в интерфейсе:

| Ключ | Название | Примеры ключевых слов в тексте OCR |
|---|---|---|
| `blood` | Кровь | «анализ крови», «общеклинический анализ крови», «гемоглобин», «гематокрит», «лейкоциты», «эритроциты», «тромбоциты», «СОЭ», «коагулограмма» |
| `hormones` | Гормоны и биохимия | «биохимический», «глюкоза», «холестерин», «билирубин», «АЛТ», «АСТ», «ТТГ», «Т4», «ферритин», «витамин D», «кортизол» |
| `urine` | Моча | «анализ мочи», «общий анализ мочи», «уробилиноген», «относительная плотность мочи» |
| `stool` | Кал | «копрограмма», «кал на», «фекалии» |
| `smears` | Мазки и цитология | «мазок», «цитологическое исследование», «онкоцитология», «ПАП-тест» |
| `imaging` | МРТ, КТ, УЗИ и рентген | «МРТ», «КТ», «УЗИ», «рентген», «флюорография», «допплер» |
| `function` | ЭКГ и функциональная диагностика | «ЭКГ», «спирометрия», «СМАД», «суточное мониторирование» |
| `other` | Прочее | (всегда совпадает — фолбэк) |

Живёт в новом модуле **`backend/app/services/doc_categories.py`**:

```python
@dataclass(frozen=True)
class DocCategory:
    key: str
    label: str
    keywords: tuple[str, ...]

DOC_CATEGORIES: tuple[DocCategory, ...] = (...)
OTHER: DocCategory = DocCategory("other", "Прочее", ())

def classify(text: str) -> DocCategory:
    """Первая категория словаря, в чьи ключевые слова попал текст OCR; иначе Прочее."""

def suggest_title(text: str, category: DocCategory, uploaded_at: str) -> str:
    """Заголовок бланка (первая строка-раздел, ≤120 символов) или фолбэк «{label} · {дата}»."""
```

Проверка ключевых слов — регистронезависимая, по подстроке; состав слов
расширяется только парами, проверенными на реальных бланках (та же философия,
что в `_TERM_RULES` постобработки: «не угадывать»).

## Изменения по слоям

### 1. Схема БД (`backend/app/database.py`)

- `DOCUMENTS_TABLE`: колонка `title_source TEXT NOT NULL DEFAULT 'auto'`
  (`'user'` / `'auto'`) и `category TEXT NOT NULL DEFAULT ''` (ключ категории;
  пусто = ещё не классифицировано).
- `_migrate()`: два `ALTER TABLE documents ADD COLUMN ...` по существующему
  паттерну (блок `doc_columns`, строки 303–318) + обновление снапшота колонок.

### 2. Загрузка (`backend/app/routers/documents.py`)

- `upload_document`: `title_source = 'user'` если пользователь передал непустое
  название, иначе `'auto'` (текущий фолбэк `title=filename` сохраняется как
  временное имя).
- После успешного INSERT — `ocr.enqueue(doc_id, user_id)` (если
  `config.ocr_enabled()` и документ допустимого типа): авто-OCR сразу после
  загрузки. Существующие лимиты очереди (20 задач, 3 попытки) действуют как есть;
  при отказе enqueue загрузка всё равно успешна (название можно получить кнопкой).
- `_doc_payload`: добавить `category` и `title_source`.

### 3. Распознавание (`backend/app/services/ocr.py`)

- `process_one()` после `clean_text` (строка 172): `category = doc_categories.classify(clean_text)`;
  если `title_source == 'auto'` — новый `title` из `suggest_title()`.
- Финальный UPDATE дополняется `category=?, title=?` (title — только для auto).
- Аудит: `record(db, "document.classify", ..., details={"category": ..., "titled": bool})`
  — без содержимого документа (формат как у `document.ocr.postprocess`).
- Новый `backfill_categories()` по шаблону `backfill_postprocessed()`:
  для всех `ready`-документов с пустой `category` — классификация по
  `ocr_text_clean` и (если `title_source='auto'`) переименование. Идемпотентно,
  вызывается из `worker_loop()` рядом с `backfill_postprocessed()`.

### 4. Фронтенд

- `types.ts`: `DocumentItem` + `category: string`, `title_source: 'user' | 'auto'`.
- `DocumentsTab.tsx`:
  - список группируется по категории в порядке справочника (`other` последним);
    заголовок группы + счётчик; внутри группы — по дате (текущая сортировка);
  - бейдж категории у документа (паттерн `RiskSystems.tsx` — словарь
    `key → label`, тот же список ключей);
  - у документа с `title_source='auto'` после OCR — обновление названия в списке
    (поллинг OCR уже обновляет `docs`, добавить `title`/`category` из ответа
    `GET /api/documents` или расширить `GET /{id}/ocr`);
  - форма загрузки: подпись поля «Название» уточняется («необязательно — подставим
    по распознанному тексту»).
- В кабинете врача (`DoctorPatients.tsx` / `DoctorPatient.tsx`) — без изменений:
  заголовки документов приходят те же.

### 5. Чат-агент (опционально, второй шаг)

`chat_agent.py::_my_documents` может добавить `category` в выборку — ассистент
сможет отвечать «из моих анализов крови» точнее. Не блокирует основной этап.

## Этапы внедрения

1. **Справочник и классификатор** — `doc_categories.py` + юнит-тесты
   (тексты из `tests/test_chat_analyses.py::LAB_TEXT`, реальные бланки, негативные
   случаи: пустой текст, нерелевантный текст → `other`).
2. **Схема и API** — колонки, миграция, `_doc_payload`, `title_source` в upload.
3. **Интеграция** — авто-OCR после загрузки, классификация и переименование в
   `process_one`, аудит, `backfill_categories`.
4. **Интерфейс** — группировка, бейджи, обновление названия по поллингу.
5. **Приёмка** — прогон тестов, smoke в браузере: загрузка без названия → через
   несколько секунд документ в группе «Кровь» с названием из бланка; загрузка с
   ручным названием → название не меняется.

## Ограничения

- Классификатор основан на ключевых словах: бланк без узнаваемых слов попадает в
  «Прочее» — это корректное поведение, а не ошибка; словарь расширяется по мере
  реальных бланков.
- Авто-название использует заголовок бланка как он распознан: OCR-ошибки в
  заголовке попадут в название (проверяется по кнопке «Исходный текст»).
- Авто-OCR после загрузки ускоряет заполнение очереди; лимиты (20 задач/3 попытки)
  остаются механизмом защиты от злоупотреблений.
