## Что сознательно не делаем и почему

1. **Партнёрские API лабораторий напрямую** — публичного API у Инвитро/Гемотест нет (№26 проверил поиском); только B2B-договор внутри П.3.
2. **Пуши** — нет мобильной обёртки; напоминания — email и/или Telegram (№29, №30).
3. **Восстановление пароля по email/SMS** — нет канала; сейчас только очно через администратора филиала; фиксируем честно в UI (№7).
4. **Redis для rate-лимитов и гварда** — SQLite WAL с timeout=10 (database.py:206) выдерживает локальный деплой; Redis — в комментарии до горизонтального масштабирования (№11, №24).
5. **Чекбокс «поделиться документом с врачом» в «Сейчас»** — формулировка «видны врачам вашего филиала» + лог открытий; тонкий шеринг — после audit_log (№4 предлагал оба варианта).
6. **allow_past для пациентов** — запрет прошедших дат без исключений; флаг только врачу (№15).
7. **МИС-интеграция как основа записи** — сначала собственная модель слотов (№1); МИС позже и через адаптер (№32).
8. **Переезд на PostgreSQL / ORM / микросервисы** — не запрашивался; SQLite WAL выдерживает объёмы клиники; пересмотр при сетевом деплое >1 сервера.
9. **LLM-диагностика** — модель не может изменить риск (analyze.py:29); расшифровка лабораторных — только текстом, без права менять green/yellow/red.
10. **Развёрнутая ИТ-инфраструктура бэкапов (S3-версионирование, DR-план, репликация)** — ночной `sqlite3 .backup` на второй диск + README достаточно для одного сервера клиники; пересмотр при тираже/втором сервере. Отказ только от heavyweight-инфраструктуры, не от самих бэкапов — С.9 обязательны.
11. **Админ-панель управления пользователями (UI)** — только CLI-инструменты (паттерн tools/make_invite.py): disable и отзыв сессий — CLI в С.3, self-service — Д.6; UI-админка не запрашивалась ни одним аналитиком.
12. **Code-splitting при LAN-деплое** — при ветви «LAN-сервер в клинике» (С.11) Д.8 отклоняется как низкоценный: 528 КБ gzip с локального сервера не влияют на конверсию; возврат — при переходе на публичный доступ.
13. **Тираж на публичный доступ до С.2+С.5 (маскирование+согласие) и С.9 (бэкапы)** — карта ветвится по С.11, но юридический минимум и долговечность данных обязательны в обеих ветвях; «сначала продуктив, согласие потом» — не вариант для спецкатегории ПДн.
